# WebEyeTrack 비교판

실행 중인 주소: http://127.0.0.1:8765/

서버가 종료됐으면 이 폴더의 `start.cmd`를 실행하거나 `node server.cjs`를 실행합니다. 브라우저에서 전체 화면을 먼저 켜고 카메라 버튼을 누릅니다. 작업공간의 기존 단일 HTML은 `http://127.0.0.1:8765/legacy.html`에서 비교할 수 있습니다. 화면의 EyeGestures 링크는 공식 사이트의 외부 데모를 여는 것으로, 이 앱에 EyeGestures 엔진을 통합한 것은 아닙니다.

## WebGazer 테스트

주소: http://localhost:8765/webgazer.html

WebGazer 3.5.3 공식 배포본을 고정 버전으로 보존하고 같은 화면에 연결했습니다. 카메라를 켠 뒤 9개 점을 바라보면 점마다 최대 5개 프레임을 보정 데이터로 기록합니다. 마우스 클릭·이동 자동 학습은 비활성화했고, 브라우저에 참가자 보정을 저장하지 않습니다. 새 참가자는 처음부터 다시 보정합니다.

별도 5점에서 가로·세로 오차의 90백분위 값을 픽셀로 표시합니다. 중앙값만 쓰면 좌우 또는 위아래의 큰 오류가 가려질 수 있으므로 축별 요약에는 90백분위를 사용합니다. 테스트판은 기존 비교판과 같은 기준으로 게임 시작 여부를 판단합니다. 사용자 환경의 시선 정확도를 보장하지 않습니다.

검증에 실패해도 `추적 표시만 보기`를 선택하면 채점 없이 추정 시선을 관찰할 수 있습니다. 화면의 원 5곳을 번갈아 보면서 방향이 맞는지 확인합니다. 이 경로는 검증 성공이나 게임 시작으로 처리하지 않습니다.

실제 라이브러리 실행 검증은 PowerShell에서 `$env:EYE_WEBGAZER='1'; node smoke.cjs`로 수행합니다. 공개 사진으로 45개 보정 샘플이 기록되고, 움직이지 않는 눈을 다른 점에 맞춘 것으로 학습했을 때 별도 검증이 실패하는지 확인합니다. 일반 UI 클릭이 학습에 들어가지 않는 것과 카메라 재보정도 검사합니다. 이 검증은 사람이 점을 따라보는 정확도 검증이 아닙니다.

출처 및 라이선스: https://github.com/brownhci/WebGazer (GPLv3), 다운로드 파일 해시와 출처는 `webgazer-upstream.json`에 기록했습니다.

## 추적 방식

### RealEye Light 비교판

`http://localhost:8765/realeye.html`에서 공식 `@realeye-io/webcam-eyetracker-light-open@1.1.0`을 실행합니다. 원본 라이브러리의 17점 패턴과 `calibrate` / `predict` API를 사용하며, 각 점에서 5개 눈뜬 프레임(총 85장)을 수집합니다. 타겟 영역 좌표를 viewport CSS 픽셀로 변환하여 학습하고 출력은 타겟 영역으로 다시 변환합니다. 보정 중 추정 커서는 숨깁니다.

GPU 초기화가 실패하면 CPU로 다시 시도합니다. 별도 5점 검증에는 새 프레임을 쓰며, 다른 비교판과 동일한 표시 필터를 사용합니다. RealEye의 게임 시작 허용 기준은 아래 체험 설정을 따릅니다. 검증 실패 시 ‘추적 표시만 보기’로 좌표를 관찰할 수 있습니다. 이미지 수집은 버튼으로 시작하며 영상·보정 이미지는 업로드하지 않습니다. 보정 후 수집 이미지는 메모리에서 해제하고, 다시 보정할 때 새 모델을 만듭니다.

RealEye 체험 판정은 `realeye-profile.js`에서 넉넉하게 설정합니다. 검증 중앙값 0.22, p90 0.34, 점별 최악 중앙값 0.32, 중앙점 0.22 이하를 허용합니다(타겟 영역 정규화 거리). 실측 오차는 그대로 표시합니다. 타겟 반경은 p90 + 0.04를 기준으로 0.22-0.30 범위이며, 이미 타겟 안에 있을 때 경계 여유 0.03을 줍니다. 연속 이탈 1.2초 이후 초당 에너지 6%를 차감합니다. 인식 끊김에서는 채점을 멈춥니다. `node game-check.cjs`로 체험용 검증 허용·큰 오차 거절·경계 여유·이탈 유예·인식 끊김을 검사합니다.

상용 RealEye 전체 제품과 구분되는 Light Open 라이브러리이며, 출처와 npm 무결성은 `realeye-upstream.json`에 기록합니다. 라이선스는 AGPL-3.0-or-later / RealEye Commercial 이중 라이선스입니다. 공식 소스와 라이선스를 비교판 하단에서 확인할 수 있습니다. 수정한 통합 코드는 이 폴더에 있습니다.

`$env:EYE_REALEYE='1'; node smoke.cjs`로 실제 라이브러리의 얼굴 모델·17점 보정·별도 검증·재연결을 테스트합니다. 정지된 테스트 사진은 점을 눈으로 따라갈 수 없으므로, 검증 실패가 정상입니다. 실제 사람의 추적 정확도는 이 검사로 측정되지 않습니다.

### WebEyeTrack 비교판

- 공식 WebEyeTrack / BlazeGaze CNN과 얼굴 랜드마크를 별도의 Worker에서 실행합니다.
- 9점에서 각 3-4개의 눈 이미지·고개 벡터·얼굴 위치를 수집하고 공식 `adapt` API로 개인 보정을 적용합니다.
- WebGL 사용 가능 시 CNN 개인 학습 1단계와 좌표 보정을 적용합니다. GPU를 사용할 수 없으면 TensorFlow WASM으로 추론하고 CNN 출력에 대한 affine 좌표 보정을 적용합니다. WASM 모드에서는 CNN 가중치 개인 학습을 수행하지 않습니다.
- 모델의 viewport 기준 좌표를 타겟 영역 좌표로 변환합니다. 화면의 다른 버튼 클릭으로 보정 데이터가 오염되지 않도록 공식 Proxy의 전역 클릭 학습은 사용하지 않습니다.
- 별도 5점 검증을 통과해야 게임을 시작합니다. 게임과 같은 시간 기반 필터로 검증하며, 오류를 감추는 좌표 클리핑은 검증 전에 적용하지 않습니다.
- 얼굴 이탈과 눈 감김에서는 시간을 멈춥니다. 영상과 보정용 눈 이미지를 서버에 저장·업로드하지 않습니다.
- 원본 upstream 파일은 `vendor/`에 보존하고, 빌드 시 텐서 정리·눈 감김 임계값·필터 중복 처리를 보완합니다. 사용한 커밋과 다운로드 파일 해시는 `upstream.json`에 있습니다.

## 검증

흔들림 완화: WebGazer 콜백마다 샘플 번호와 측정 시간을 전달해 중복 출력의 필터 처리·검증 집계를 막습니다. 최근 3개 좌표의 중앙값과 시간 기반 저역 필터를 적용하며, 큰 이동에는 반응 속도를 높입니다. 얼굴 이탈·눈 감김·고개 위치 변화·검증 점 이동 시 필터를 초기화합니다. 검증과 게임에 동일한 필터를 사용합니다. 타겟 방향으로 좌표를 끌어당기지 않으며 일정한 방향으로 빗나가는 보정 오차는 해결하지 않습니다.

큰 튐 추가 억제: 현재 표시 위치에서 정규화 거리 0.18 이상 떨어진 출력은 가까운 영역(거리 0.09)에 3회 이상, 80ms 이상 지속될 때 반영합니다. 표시 위치의 최대 이동 속도는 초당 정규화 거리 2.4로 제한합니다. 1-2프레임의 큰 튐이 빠른 필터를 발동시키던 문제를 막습니다. 지속되는 화면 밖 출력은 그대로 반영하여 검증 오차가 숨겨지지 않게 합니다.

`node filter-check.cjs`의 고정 시드 합성 노이즈에서 RMS 흔들림이 약 59% 감소했고, 큰 좌표 이동 후 90% 도달 시간은 15/30/60Hz에서 400/400/383ms였습니다. 2프레임의 큰 튐 억제, 최대 이동 속도, 지속되는 화면 밖 오차 노출도 검사합니다. 실제 사람의 정확도 향상 수치가 아닙니다. 안정화를 위해 응답 지연이 생깁니다.

`node smoke.cjs`는 이 PC의 숨겨진 Chromium과 공개 테스트 사진·가상 카메라를 사용합니다. 실제 CNN 로딩, 추론, 개인 보정 API, 얼굴 미검출 처리를 검사합니다. 별도의 합성 출력으로 UI의 9점 보정, 5점 검증, 게임 종료와 재시작도 확인합니다. npm 설치 후 `npm run build`로 다시 빌드할 수 있습니다.

실제 모델 실행에서 WASM 모드의 준비 후 추론 중앙값 148ms, p90 157ms를 측정했으며 반복 추론의 텐서 수는 94개로 유지됐습니다. 이는 특정 테스트 사진과 테스트 환경의 실행 속도이고, 사람의 시선 정확도나 부스 PC에서의 성능 보장이 아닙니다. 첫 추론은 초기 준비 때문에 약 1.2초가 걸렸습니다.

실제 참가자에게 보정 점을 바라보게 해 가로·세로 오차와 보정 성공률을 비교해야 채택 여부를 판단할 수 있습니다. 합성 UI 검증이 실제 시선 정확도를 증명하지 않습니다.
